# Changelog

## 1.0.1 (2026-10-22) — Readable report with provenance

- The report is a report document for readers who do not know the plugin's internals: an overall verdict and conclusion first, then this plugin's viewpoints (why each matters, its evidence, verdict and impact), then Claude Code's standard prompt diagnosis as a separate section that shows each of its findings with its own reason, recommended timing ("before using it", "when there is time", and "your call" for low-confidence findings, which are applied only when named), details, and a closing "next action" with numbered choices and the number of findings that would remain for each. Choice 4 shows the improved text without changing any file.
- Every item says where it comes from: a paper (peer-reviewed or preprint), an Anthropic document, the standard prompt diagnosis, or this plugin's own check or judgment. The report no longer shows internal criterion numbers, script field names, commands or costs.
- The diagnosis is no longer mapped onto a fixed list of categories, so new kinds of findings from Claude Code appear without updating the plugin. When the diagnosis and this plugin flag the same spot, the finding is numbered once.
- New `skills/prompt-design-review/scripts/run-audit.py` runs the diagnosis from an empty folder in safe mode with only reading tools (Read, Grep, Glob), so the user's own `~/.claude` CLAUDE.md, rules, skills and plugins no longer leak into it and it cannot change the target, and returns one JSON line; SKILL.md calls it instead of carrying the command-line rules.
- Rule count is now a caution, not a finding: check.py estimates rules from directive sentences instead of lines, adds the instruction files Claude Code loads with the target (`rule_load`, `--no-context` to leave them out) and lists the target's counted sentences (`directive_candidates`) so the review judges which are rules and in which stage of the asset's work each applies; the report always gives the busiest stage's count once judged (this plugin's judgment), a caution above the guide of 40 (this plugin's own choice) says that compliance falls as more rules apply at once (Eliav 2026, preprint), that where it starts shifts with the model and the rules, and suggests scripts or hooks for machine-judgeable rules or splitting the stage, without study numbers; `docs/rule-count-experiment.md` records a small experiment on current Claude models as background; a separate note names the loaded files when they push the loaded total over, and check.py's summary says "total loaded".
- Things that were checked but not shown are now reported: references not probed, operations the diagnosis was refused, the files compared for rule conflicts, and that a document review cannot show improved behavior (ACES, preprint).
- A fourth overall verdict, "no findings in what could be checked", is used when something could not be checked.
- Evidence for verification and stop conditions and for tool-call contracts now cites Anthropic documents instead of an older OpenAI guide; the enforcement-point viewpoint cites Anthropic's statement that hooks run deterministically while CLAUDE.md instructions are advisory.

## 1.0.0 (2026-10-22) — Initial release

- `prompt-design-review` skill: reviews SKILL.md, CLAUDE.md, rules, subagent definitions and system prompts, and merges the result with Claude Code's built-in `/doctor prompt-audit` into one report.
- Seven design criteria the built-in audit does not cover: compatible constraints, delegation instructions, approval and autonomy boundaries, verification and stop conditions, tool-call contracts, connection to external verification, and proposed enforcement points for machine-checkable rules.
- Substitute checks when the built-in audit is unavailable or the target is meant for another vendor's model.
- `skills/prompt-design-review/scripts/check.py` mechanical check (Python standard library only): instruction and prohibition line counts in English and Japanese, unresolved paths, duplicated sentences, version comments and frontmatter, with `--strict` for hooks and CI and a `--self-test`.
- Targets are rewritten only for the findings the user selects; the report is written in the user's language.
- Distributed as a Claude Code plugin with its own marketplace.
