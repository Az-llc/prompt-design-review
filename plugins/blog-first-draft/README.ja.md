# blog-first-draft

終わった作業の記録から、日本語の技術記事（Zenn など）の最初の版を作る Claude Code のプラグインです。文章を書かせる前に、渡すものを整えます。

[English README](README.md)

## 何をするか

書いた後に直すのではなく、書かせる前に次のものを用意します。

- **作業中の自分の発言。** Claude Code の会話の記録から、著者の発言だけをスクリプトで集めます。なぜそれを試したか、結果をどう受け取ったかは、作業の記録には残りにくく、発言に残っています。
- **主張の骨組み。** いちばん意外なこと、読者が順に抱く問いと答え、答えの出どころ、答えと合わない数字、記事に入れないもの。文章の前に作り、数字と合わない言い方はここで直します。
- **題と冒頭。** 題は、切り口の違う案から著者が選びます。冒頭だけを先に書き、著者が納得するまで直してから、残りを書きます。

本文は、作業の会話を知らないサブエージェントが書きます。会話を知っている側が書くと、その会話の中だけで通じる言葉が、気づかれないまま記事に入るためです。書いた後は、同じく何も知らないサブエージェントが 1 度だけ読み、挙がった所を 1 度だけ直します。

避ける言葉の一覧は持っていません。文体を後から整えることもしません。

## 限界

- 確かめたのは、作業の記録から書く日本語の技術記事だけです。ほかの種類の文書では試していません。
- サブエージェントは、プロジェクトの指示ファイル（CLAUDE.md など）を読み込みます。持っていないのは会話の文脈で、プロジェクトの決まりではありません。
- 発言を集められるのは、残っている会話の記録からだけです。Claude Code は、`cleanupPeriodDays` より長く更新の無い記録を消します。
- 1 回の実行で、サブエージェントを 5 つ動かします（骨組み・冒頭・本文・読む・直す）。資料を丸ごと渡す段が 3 つあるので、資料が長いほど使用量が増えます。
- 読む段は、本文を書いたモデルより力のあるモデルを起動できるときだけ動きます。起動できないときは、最初の版をそのまま届けます。

## 本文を別のモデルに書かせる

最初に、本文を誰が書くかを聞きます。何も指定しなければ、サブエージェントが書きます。

別のモデルやサービスに書かせたいときは、そう答えてください。skill は依頼文を 1 つのファイルにまとめて待ちます。そのファイルを渡して、返ってきた記事を作業フォルダに置くと、続きを進めます。

依頼文のファイルには、資料と発言が全部入っています。外のサービスに渡してよいかは、ご自身で判断してください。

別のモデルは、依頼文の書き方の指示を守らないことがあります。確かめたときは、図を使わない指示があっても図を入れ、決まった冒頭の文を数文字変えました。冒頭は skill が元に戻しますが、そのほかの形は戻しません。

## インストール

```text
/plugin marketplace add Az-llc/prompt-design-review
/plugin install blog-first-draft@az-llc
```

## 使い方

```text
/blog-first-draft:write
```

このコマンドを打ったときだけ動きます。Claude が自分から始めることはありません。

始めると、次のことを聞かれます。作業の記録のファイル、その作業をした会話、掲載先と読者、記事で残したい 1 文、取り組んだ理由、題（決まっていれば）、記事への注文、本文を誰が書くか。

## 前提

- Claude Code
- Python 3.10 以降

スクリプトはネットワークに接続しません。読むのはローカルの会話の記録と指定したファイルで、書くのは作業フォルダの中だけです。作業フォルダはシステムの一時フォルダに作り、記事を届けた後に消します。

## 更新について

記事を書く中で確かめた段取りを、そのまま形にしたものです。更新の約束はしません。作者が自分で使っていて直した分は、反映することがあります。
